# 어깨 너머(OTS) 구도 결함과 수정 (2026-09-26)

STEP 12 테스트에서 찾은 결함이다. 솔버는 "어깨 너머 적용 성공"이라고 보고했지만 실제 화면에는
앞사람이 보이지 않았다. 원인을 잡아 고쳤고, 재발을 막는 테스트를 넣었다.

## 증상

`UPT.ReferenceE2E`로 두 인물 장면에 어깨 너머 샷을 만들면:

- 로그: `[어깨 너머] Shot_02: 'AutoHero' 어깨 너머(앞사람 화면 오른쪽, 렌즈 44mm)` — 성공으로 보고
- 플랜: `over_shoulder{actor, side, edge_x: 0.889}` — 정상 저장
- **실제 렌더**: 오른쪽 지정 시 앞사람은 우하단 구석의 덩어리뿐, 왼쪽 지정 시 좌측 끝의 그림자뿐
- 자동 검증: `어깨 너머 앞사람 right → not_detected`

`not_detected`를 "세그멘테이션이 마네킹을 못 잡아서"로 넘겼던 것이 오판이었다. 앞사람이 정말로 프레임 밖에 있었다.

## 원인

`FUPTReferenceBlockingSolver::SolveOverShoulderCamera`가 **앞사람의 가로 위치만** 검사했다.

- 카메라 높이를 앞사람 키의 90%로 **고정**했다.
- 앞사람 어깨를 투영해 `Edge.X`가 목표 가장자리에 오는지만 봤다. `Y`는 어디에도 쓰이지 않았다.

주 피사체를 화면 아래쪽에 두는 샷(`subject_screen_y = 0.76`)에서는 카메라가 위를 향한다.
카메라보다 낮은 곳에 있는 앞사람은 그만큼 화면 아래로 밀려 프레임을 벗어난다.
가로 조건은 여전히 만족하므로 솔버는 성공으로 판단했다.

## 수정

같은 함수에서:

1. 카메라 높이를 고정하지 않고 앞사람 키의 **65~105%** 구간에서 함께 탐색한다.
2. 앞사람 어깨와 머리를 둘 다 투영해 세로 조건을 검사한다.
   - 어깨 화면 Y가 `0.45~1.05` 밖이면 제외 (위면 피사체를 가리고, 아래면 프레임 밖)
   - 머리 화면 Y가 `0.85`보다 아래면 제외 (머리가 보여야 '어깨 너머'로 읽힌다)
3. 비용 함수에 어깨 세로 위치 항을 더한다(목표 0.85).

## 확인

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 오른쪽 지정 렌더 | 우하단 구석 덩어리 | 오른쪽 가장자리에 어깨가 제대로 걸림 |
| 왼쪽 지정 렌더 | 좌측 끝 그림자 | 왼쪽에 머리·어깨가 걸림 |
| 대상 인물 크기 | 0.90배 | 0.97배 |
| 자동화 테스트 | 5/5 통과(세로 검사 없음) | 11/11 통과(세로 검사 포함) |

테스트(`UPTReferencePlanTests.cpp`의 `Framing.OverShoulder`)는 주 피사체를 화면 위쪽(0.42)과
아래쪽(0.76)에 두는 두 경우를 모두 돌리고, 앞사람 어깨가 `0.4~1.1`, 머리가 `0.9` 안에 있는지 확인한다.
수정 전 코드에서는 0.76 케이스가 실패한다.

## 이어진 수정: 검증기의 주 피사체 측정 (같은 날)

구도를 고친 뒤 왼쪽 지정 케이스의 검증 점수가 63 → 42로 떨어졌다. 디버그 이미지로 확인한 실제 원인은
주 피사체 **선택**이 아니었다. 그 프레임에서 앞사람은 아예 검출되지 않았고, 검출된 사람은 주 피사체 하나뿐이었다.

문제는 **측정**이었다.

- 주 피사체 검출 상자가 `[608, 178, 1099, 717]`, 프레임 높이가 720 — **몸이 화면 아래로 잘려 있었다.**
- `upt_pose_render_verify.py`는 보이는 부분으로 몸 축을 세우고 조준 높이까지 그 축을 늘여 조준점을 잡는다.
  인물이 39° 기울어 서 있어서 그 연장선이 옆으로 밀렸다. 축점 x=0.732, 상자 중앙 x=0.667, 기준 0.641.

### 고친 내용 (`upt_pose_render_verify.py`)

1. `is_cropped()` — 검출 상자가 프레임 가장자리 4px 안에 붙으면 잘린 것으로 본다.
2. `measure_focus()` — 잘린 몸은 가로 위치를 축 연장선 대신 **검출 상자의 가로 중앙**으로 잰다.
   결과 행에 `subject_measure`(`body_axis` / `box_center`)로 어느 쪽을 썼는지 남긴다.
3. `drop_over_shoulder_foreground()` — 어깨 너머 샷에서 지정한 쪽 가장자리에 붙어 있고 다른 인물보다
   1.5배 이상 크게 잡힌 검출은 후보에서 뺀다(이번 사례에선 발동하지 않았지만, 앞사람이 검출될 때를 위한 대비).
4. 주 피사체 선택 거리도 같은 측정 함수를 쓰게 통일했다.

### 결과

| 케이스 | 수정 전 | 수정 후 |
|---|---|---|
| 왼쪽 Shot_02 위치 오차 | +0.091 | **+0.026** |
| 왼쪽 Shot_02 점수 | 41.6 | **63.4** |
| 왼쪽 전체 점수 | 70.7 | **76.8** |
| 오른쪽 Shot_02 점수 | 80.2 | 79.0 (측정 방식만 바뀜) |
| 회귀 검사 | — | 10개 스위트 전부 통과 |

왼쪽 케이스가 아직 63인 것은 위치가 아니라 **크기**(0.80배) 때문이다. 몸이 잘려 전신 키를 추정으로 잡는 탓이며,
위치 오차와 달리 이건 실제로 레퍼런스보다 인물이 작게 담겼다는 뜻이기도 하다.

## 이어진 수정 2: 어깨 너머 자동 검증을 실제로 작동하게 (같은 날)

`over_shoulder_found`가 계속 `not_detected`였다. 먼저 두 모델이 앞사람을 볼 수 있는지 직접 쟀다.

| 방법 | 수정된 렌더에서 앞사람 검출 |
|---|---|
| YOLOX 인물 검출 | 0명 (주 피사체 1명만) |
| DeepLab 분할 | 0개 |

둘 다 실패한다. 화면에 또렷이 보이는데도 그렇다 — 카메라에 아주 가까운 무늬 없는 마네킹의 어깨·머리 조각은
사람 형태로 읽히지 않는다. **이미지 인식으로는 이 검증을 할 수 없다.**

### 고친 방법: 앞사람을 숨기고 한 장 더 찍어 차이를 본다

- C++ (`UPTPoseReferenceAnalyzer.cpp`): 어깨 너머 샷이면 SceneCapture의 `HiddenActors`에 앞사람을 넣고
  `shot_NN_nofg.png`를 한 장 더 찍는다. 액터 상태는 건드리지 않는다. manifest에 `image_without_foreground`,
  `over_shoulder_actor`, `over_shoulder_side`를 남긴다.
- Python (`upt_pose_render_verify.py`): `measure_hidden_foreground()`가 두 장의 차이로 마스크를 만들어
  면적·경계 상자·방향을 낸다. 방향은 화소 무게중심으로 정한다(앞사람이 지던 그림자도 함께 사라져 차이에
  섞이는데, 그림자는 얇게 퍼지므로 무게중심이 흔들리지 않는다). 면적이 화면의 1% 미만이면 `not_in_frame`.
  모델을 전혀 쓰지 않는다. 숨긴 캡처가 없는 예전 manifest는 기존 분할 방식으로 넘어간다(`over_shoulder_check` 필드로 구분).

### 결과

| 케이스 | 수정 전 | 수정 후 |
|---|---|---|
| 오른쪽 | `right → not_detected` | **`right → right`** (면적 8.2%, 상자 x 0.455~0.999) |
| 왼쪽 | `left → not_detected` | **`left → left`** (면적 7.4%, 상자 x 0.000~0.801) |
| 차이가 없을 때 | — | 면적 0.0 → `not_in_frame` |

이제 앞사람이 프레임 밖으로 빠지는 이번 같은 결함은 사람 눈 없이 자동으로 잡힌다.

## 이어진 수정 3: 위치·크기 측정 규칙을 데이터로 정하기 (같은 날)

잘린 몸의 전신 키 추정이 크기 점수를 흔든다고 적었다. 고치기 전에 **정답을 만들어 재 봤다.**

manifest에 엔진이 계산한 정확한 값을 추가했다(`UPTPoseReferenceAnalyzer.cpp`).

- `subject_screen` — 카메라가 주 피사체를 조준한 정확한 화면 위치 (이미 있던 값)
- `subject_screen_height` — 주 피사체 Bounds의 전신이 화면에서 차지하는 정확한 높이 (새로 추가)

### 크기: 정확한 값으로 바꾸면 오히려 나빠진다

| 샷 | 검출 추정 | 기하 실측 | 차이 |
|---|---|---|---|
| Shot_01 (전신 보임) | 0.380 | 0.397 | -4% |
| Shot_02 | 1.779 | 1.875 | -5% |
| Shot_03 | 1.868 | 1.495 | **+25%** |
| Shot_04 | 1.243 | 1.349 | -8% |
| Shot_05 | 3.689 | 3.323 | +11% |

추정 오차는 -8%~+25%로 확실히 크다. 그런데 크기 점수를 기하 실측으로 바꾸자 **점수가 나빠졌다**
(Shot_03 46→21, Shot_05 93→80, 전체 79.4→71.7). 레퍼런스 쪽 키도 같은 추정기가 외삽한 값이라,
한쪽만 정확한 값으로 바꾸면 두 값이 공유하던 편향이 깨지기 때문이다.

**그래서 크기는 레퍼런스와 같은 추정기 값끼리 비교하도록 되돌렸다.** 기하 실측은 결과에
`geometric_height`·`size_confidence`(추정/실측)로 남겨, 추정이 얼마나 빗나갔는지 볼 수 있게만 했다.

### 위치: 세 규칙을 정답에 대고 채점

`subject_screen`을 정답으로 두고 두 장면 15샷에서 쟀다.

| 규칙 | 평균 오차 | 중앙값 | 최대 |
|---|---|---|---|
| 몸 축 연장(기존) | 0.052 | 0.021 | **0.235** |
| 검출 상자 가로 중앙 | **0.031** | 0.025 | **0.115** |
| 축을 상자 폭 ±10%로 제한 | 0.034 | **0.013** | 0.156 |

중앙값만 보면 ±10% 제한이 낫지만 크게 빗나가는 경우가 남는다. 회귀 검사용 지표는 최악을 줄이는 쪽이
중요하고 규칙도 단순해서, 평균·최대가 모두 가장 좋은 **상자 가로 중앙**을 쓴다. 세로는 조준 높이 비율이
뜻을 갖는 값이라 그대로 몸 축에서 읽는다.

(±10% 제한을 실제로 적용해 보니 투샷 전체 점수가 76.7 → 72.9로 떨어졌다. 중앙값을 쫓다 실제 점수를
나쁘게 만든 셈이라, 평균·최대 기준으로 되돌렸다.)

### 결과

| 세트 | 기존(몸 축) | 지금(상자 중앙) |
|---|---|---|
| 투샷 5샷 전체 점수 | 70.7 | **76.7** |
| 투샷 평균 \|가로 오차\| | 0.035 | **0.012** |
| 쇼츠 20샷 전체 점수 | 23.0 | 23.4 |
| 쇼츠 평균 \|가로 오차\| | 0.061 | **0.041** |

쇼츠 세트가 23점대인 것은 측정 문제가 아니다. 20샷 중 11개가 실사 얼굴 익스트림 클로즈업이라
얼굴 없는 마네킹으로는 재현할 수 없다.

## 남은 것

- 잘린 몸의 전신 키 추정 오차(-8%~+25%)는 그대로다. 다만 이제 `geometric_height`라는 정답이 있으므로,
  분석기의 외삽 규칙 자체를 개선하려면 이 값을 시험 세트로 쓸 수 있다. 추정기를 고치면 레퍼런스 쪽
  측정도 같이 좋아지므로, 한쪽만 바꿀 때의 편향 문제도 생기지 않는다.
- 숨긴 캡처는 어깨 너머 샷에만 찍으므로 비용은 거의 늘지 않는다. 다른 샷에도 쓰면
  '이 인물이 화면에 실제로 보이는가'를 같은 방식으로 잴 수 있다.
